# Before / After

## 例 1，去掉“不是 A 而是 B”

原文：

这不是一次简单的模型更新，而是一次开发范式的重构。真正值得关注的是，模型已经开始深入软件开发的核心流程。

改写：

新版本不只生成代码，还能继续执行测试、读取错误信息并修改结果。开发者原本需要手动来回切换的几步，现在可以交给同一个 Agent 连续完成。

为什么这样改：原句的“简单更新、范式重构、真正值得关注”都在宣布重要性，改写后直接给出工作流发生了什么变化。

## 例 2，去掉冒号

原文：

OpenAI 最近连续调整 API 定价、Codex 配额和开发工具，目标很明确：让开发者更多留在自己的平台里。

改写：

OpenAI 最近连续调整了 API 定价和 Codex 配额，也在继续补开发工具。几项动作都在降低平台内开发的成本，开发者留在这套工具链里的理由比以前更多了。

为什么这样改：删除“目标很明确”这个判断壳，也不用冒号直接灌输结论。

## 例 3，去掉“这意味着”

原文：

模型价格又下降了。这意味着 AI 正在进一步走向普及。

改写：

模型价格又下降了。同样预算现在能处理更多请求，一些过去因为成本只在测试环境使用模型的团队，也更容易把它接进日常流程。

为什么这样改：把“普及”拆成可观察的使用变化。

## 例 4，去掉破折号和概念升级

原文：

AI 正在进入下一个阶段——从聊天工具变成真正的生产力工具。

改写：

以前很多人主要拿 AI 问问题，现在越来越多产品开始让模型直接读文件、改代码、跑任务和调用外部工具。

为什么这样改：不用“下一个阶段”和“生产力工具”这种大词，直接写行为变化。

## 例 5，去掉伪总结

原文：

新版本速度提升了 40%，价格下降了 20%。也就是说，用户现在可以用更低的成本获得更好的体验。

改写：

新版本速度提升了 40%，价格下降了 20%。

为什么这样改：第二句只是把第一句换一种说法，没有新增信息。

## 例 6，正常长文段落

原文：

价格降了。

速度快了。

能力也更强了。

这才是真正值得关注的变化。

改写：

这次更新同时动了价格、速度和能力。调用成本下降后，高频任务更容易长期跑起来，响应速度提升也减少了等待时间。对已经把模型接进工作流的用户来说，这些变化比单纯多几个 benchmark 分数更直接。

为什么这样改：合并碎段，保留完整观点，并用实际影响代替“真正值得关注”。

## 例 7，去掉段首伪标题

原文：

这番回应在技术上可以成立。软件当然不会凭空知道一栋楼十年前改成了什么用途。但它也暴露出军用 AI 最危险的一层幻觉。屏幕给出的结果越整齐，调用的数据库越庞大，操作者越容易相信系统已经替自己看过了。

改写：

软件不会凭空知道一栋楼十年前改成了什么用途，这在技术上说得通。危险在于，屏幕给出的结果越整齐，调用的数据库越庞大，操作者越容易相信系统已经替自己核对过目标。

为什么这样改：原来的首句只负责给本段报幕。改写把判断接到具体理由上，下一句继续推进风险，不再先放一句像标题的话再从头解释。

## 例 8，把句子式小标题改回真正的标题

原文：

### 那栋建筑多年前确实属于旁边的军事设施，后来被围墙隔开，改成学校，并公开运作了十多年。

美联社 7 月的调查发现，至少七年前就有分析人员认出那里是一所学校，但这条信息没有顺利传到不同情报与军事部门。到了目标制定环节，那栋楼又成了数据库里的一处军事目标。

改写：

### 消失的学校信息

那栋建筑原本属于旁边的军事设施，后来被围墙隔开，改成学校，并公开运作了十多年。美联社 7 月的调查发现，至少七年前就有分析人员认出那里是一所学校，但这条信息没有顺利传到不同情报与军事部门。到了目标制定环节，那栋楼又成了数据库里的一处军事目标。

为什么这样改：原标题是一整句正文，还提前压缩了下文。新标题只负责定位问题，原句里的事实回到正文，并按时间顺序展开。如果全文不需要分节，也可以直接删除标题。
